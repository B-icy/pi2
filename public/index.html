Contract & D2 Plan

Define a bounded acceptance contract with 1–12 steps, artifact roots, and executable check commands with timeouts.

Runnable Vertical Slice

Build a running vertical slice first. For games or graphics, verify a nonblank framebuffer before extending gameplay.

4

Executable Evidence

Run checks, capture stdout/stderr exit codes, and bind to the repository SHA-256 fingerprint. Any subsequent file edits invalidate evidence.

5

Bounded Repair Loop

At most 2 automatic follow-ups per prompt quoting failing check exit codes and output tails. Stops runaway hallucinated retries.

6

Verified Handoff

Only mark verified when every required check has passing, fresh evidence against the active source fingerprint.

Plan Contract Rules

            
    
              
  • Artifact roots: Must be product source/tests/config/docs, not ignored folders like node_modules or artifacts/.
    • 
              
  • Steps: Exactly 1–12 actionable steps.
    • 
              
  • Check command syntax: Argv arrays without an implicit shell (e.g. ["node", "--test"]).
    • 
              
  • Timeout: Bounded between 1 and 300 seconds.
    • 
              
  • Acceptance mapping: Every criterion must map to at least one valid check suite.

How Stale Evidence Invalidation Works

            
    
              
  1. Baseline Fingerprint: Before running any tests, the exact tree state is fingerprinted into a single SHA-256 digest.
    2. 
              
  2. Evidence Binding: When delivery_check passes, it permanently records the exit code along with the hash at the time of execution.
    3. 
              
  3. Source Freshness Guard: If any file is edited, deleted, or added (even in undeclared directories), the workspace hash changes.
    4. 
              
  4. Fail-Closed Verification: pendingChecks() flags all previous results as stale, preventing false verification claims!
    5.

Contract Verification Gate

          

            
          


          

            
Verification Invariants:

            
    
              
  • All declared checks must have executed cleanly (exit code 0).
    • 
              
  • Every check evidence fingerprint must match the active workspace hash.
    • 
              
  • No user-owned required checks can be missing or omitted.
    • 
              
  • If any test fails or is stale, verification will be rejected.
